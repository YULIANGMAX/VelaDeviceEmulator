# Vela 设备模拟器

此项目提取了 AIoT IDE 中模拟器相关的文件，提供新建与启动脚本，并对部分固件及宿主程序作了适配修复。

双击 **run.bat** 即可使用。

## 固件与模拟器程序修改

本项目对以下三个文件作了二进制补丁：

| 文件 | 修改原因 | 修改后的效果 |
|---|---|---|
| `sdk/system-images/vela-release-4.0/nuttx` | 带表盘固件的部分尺寸查询、系统页面和表盘容器使用固定尺寸，在其他屏幕尺寸下会裁切内容、出现底部黑带。 | 改为读取实际屏幕或父容器宽高，使相关页面和表盘容器随实例尺寸适配，消除已验证场景中的底部裁切。 |
| `sdk/system-images/vela-miwear-watch-5.0/nuttx` | 同样存在固定尺寸容器；原图片解码器还无法正确读取部分 Lua 表盘使用的旧 LVGL 图片头及小米 RLE 资源，导致图片缺失、动画效果不显示。 | 实现动态尺寸适配，并兼容已验证的旧图片资源；Lua 表盘的背景、数字及效果恢复正常。 |
| `sdk/emulator/windows-x86_64/qemu/windows-x86_64/qemu-system-armel.exe` | 原触摸判断依赖外壳推导的圆屏标记，矩形屏幕也可能按圆形过滤输入，导致原黑带区域虽能显示却无法点击。 | 改为按 `config.ini` 中的 `hw.lcd.shape` 判断矩形、圆形或胶囊形触摸范围，保留窗口四角拖动缩放。 |

尺寸适配不会自动重排固定坐标的表盘素材；图片解码修复也不代表兼容所有第三方 Lua 表盘。

## 菜单

- **数字 1、2……**：启动对应实例。
- **N**：按向导新建实例。
- **P**：移动目录或换电脑后修正全部实例路径；平常启动亦会自动修正所选实例。
- **C**：列出当前用户 .vela/vvd 下的孤立 .ini 索引，输入 Y 才删除。
- **R**：刷新列表。
- **0 / Q**：退出菜单；已启动的模拟器继续运行。

字母不分大小写。没有实例时直接按 N。

## 新建示例

1. 输入名称，例如 MyBand10。只能使用字母、数字、下划线与连字符，首位须为字母或数字；不能与已有实例重名。
2. 按编号选择型号，例如选择列表中的 xiaomi_band_10（212×520）。工具直接读取 sdk/skins/builtin 下全部型号。
3. 选择镜像；只有一个可用镜像时自动采用。
4. 核对摘要，按回车或 Y 创建；N 取消。
5. 创建完成后输入 Y 立即启动，或回车返回主菜单。

向导前面任一步输入 Q 可返回主菜单。复制数据分区需要一定时间，请勿中途关闭窗口。
每个实例的数据独立保存，修正路径不会覆盖已有数据。启动后菜单仍可使用，可选择其他实例；已运行的同名实例会拒绝重复启动。


## 迁移与错误

如整体迁移本目录到新位置或电脑，双击 run.bat 即可按自身位置生成配置，并在当前用户 .vela/vvd 下登记实例索引。

目录与当前用户配置目录需可写，通常无需管理员权限。

当前用户若有同名外部实例，工具会拒绝覆盖，请改用另一个名字。

菜单直接启动原生模拟器，退出菜单也不影响模拟器继续运行；实例数据在 vvd，勿误删。

选择不同型号只会改变屏幕与设备配置，不会自动获得对应设备的真实固件。

因为是由**固定分辨率**的设备固件修改而来，所以任何内部应用的元素位置出现错乱都属正常现象。


## 孤立索引清理

菜单按 C 或运行 .\emu.ps1 clean，仅扫描当前用户 .vela/vvd 顶层的 .ini。只有同名 .vvd 目录和索引中 path、path.rel 所指目录均不存在时，才列为可清理项。
数据在本包或其他位置的有效索引会保留；离线盘符、无法确认的路径跳过。
默认不删除，输入 Y 后仅删除列出的孤立 .ini，不会删除任何 .vvd 目录。
